# Cowork membership and invitation web panel

`MembershipInvitationPanelModel` and `CoworkMembershipInvitationPanel` are an adoption-ready, web-only presentation boundary for the audited collaboration membership authority. The surface has no production wiring. A caller must explicitly inject a client and select the current shared project and authenticated actor. With a null client, the component renders nothing and creates no timer, fetch, socket, RPC, subscription, or background work.

The injected read adapter returns one bounded page containing the current membership snapshot and pending invitation metadata. The model first requires bounded JSON-like objects with intrinsic prototypes and enumerable own data properties, then strictly decodes the page and rejects excess fields. It enforces the 128-member contract cap, caps invitations at 100, requires project-scoped unique invitation identifiers, validates role/permission fit and the 30-day interval ceiling, and bounds epoch, revision, and cursor values. It copies, deterministically orders, and freezes accepted display data so later mutation of a hostile adapter payload cannot change rendered state. The UI displays only member name/id/role and invitation id/role/creator/validity/permission count. It has no fields for secret digests, device keys, credentials, provider output, prompts, private paths, or invite tokens.

The optional creation adapter adds a deliberately narrow one-time presentation boundary. The operator must explicitly select a subordinate project role, a non-empty subset of that role's permissions, an activation delay from zero through seven days, and an integer-hour lifetime from one hour through thirty days. The immutable adapter request binds the command to the exact shared project, authenticated operator, membership epoch, membership read revision, role, ordered permission set, delay, and lifetime. A strictly decoded response must echo that complete scope and return a matching grant; excess, inherited, accessor-backed, cross-project, cross-operator, stale-authority, permission-drifted, lifetime-drifted, or identifier-colliding data fails closed. `owner` invitations and invitations at or above the actor's current role are never admitted.

The plaintext token exists only in the immediate successful adapter response and the current in-memory presentation state. The panel provides no clipboard/copy API and never puts the token in a URL, persistence, storage, history, diagnostics, provider/agent context, synchronization payload, or retry reconstruction. Dismissal, project/client/operator replacement, authority-context refresh, unmount, or error replaces the state with a token-free snapshot; late results cannot repopulate it. Further creation is blocked until the operator explicitly dismisses the presented token, preventing an accidental create from discarding the only visible copy. JavaScript strings and React snapshots cannot be securely zeroed, so this boundary promises prompt reference removal rather than impossible memory erasure. A caller must likewise avoid logging or retaining the injected response.

An indeterminate create acknowledgement locks the form and retains and retries only the exact same frozen command and scope. Changed retry input is rejected rather than silently replaying an older hidden scope. A replay is allowed to return only `already-applied` with a null secret: it never mints, requests, or claims to recover a second token. The panel then exposes the known invitation as token-lost, blocks further creation, and requires the operator to revoke that invitation before creating a new one. Creation remains absent when the adapter capability is not injected.

Invitation revocation uses the existing strict request and mutation-result contracts. The model derives authority from the current actor's membership rather than client-asserted flags, requires `project.manage-members`, and applies the same owner/admin role ceiling as the audited store. The panel permits only one active revoke across the project at a time. An indeterminate or stale result retains the exact immutable request object and command id, disables retry while reloading current membership authority, rejects epoch/revision rollback or membership changes that reuse an epoch, and offers retry only when the invitation and the actor's authority both remain current; it never generates a replacement id. If that bounded refresh proves the invitation absent, the list converges without retry. A confirmed result must have no member and the current membership epoch before the invitation disappears.

Project switches, unmount, React StrictMode effect replay, late loads, late mutations, malformed/excess payloads, cross-project invitations, duplicate ids, cursor/revision overflow, stale epochs, and actor removal all fail closed. Stale callbacks cannot repopulate a prior project's membership, invitations, or one-time token. This adoption slice deliberately adds no email, clipboard, timer, redemption, network primitive, RPC/socket, production wiring, persistence, process, provider, or agent integration. The adapter remains responsible for authenticated transport, server authorization, durable invitation filtering, diagnostics, and pagination beyond the bounded first page.
