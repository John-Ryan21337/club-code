# Cowork membership and invitation web panel

`MembershipInvitationPanelModel` and `CoworkMembershipInvitationPanel` are an adoption-ready, web-only presentation boundary for the audited collaboration membership authority. The surface has no production wiring. A caller must explicitly inject a client and select the current shared project and authenticated actor. With a null client, the component renders nothing and creates no timer, fetch, socket, RPC, subscription, or background work.

The injected read adapter returns one bounded page containing the current membership snapshot and pending invitation metadata. The model strictly decodes the page, rejects excess fields, enforces the 128-member contract cap, caps invitations at 100, requires project-scoped unique invitation identifiers, validates role/permission fit, and bounds epoch, revision, and cursor values. It copies and freezes accepted display data so later mutation of a hostile adapter payload cannot change rendered state. The UI displays only member name/id/role and invitation id/role/creator/validity/permission count. It has no fields for secret digests, device keys, credentials, provider output, prompts, private paths, or invite tokens.

This slice deliberately omits invitation creation. The audited creation result can return a one-time plaintext invitation token, but this isolated web slice has no reviewed copy surface or transport guarantee proving that the token will never be retained, replayed, logged, serialized, or restored by application state. Creation should be added only as a separate security-reviewed slice with a one-render operator-copy boundary and explicit zero-retention tests.

Invitation revocation uses the existing strict request and mutation-result contracts. The model derives authority from the current actor's membership rather than client-asserted flags, requires `project.manage-members`, and applies the same owner/admin role ceiling as the audited store. Each invitation permits at most one active request. An indeterminate failure retains the exact immutable request object and command id for retry; it never generates a replacement id. A confirmed result must have no member and the current membership epoch before the invitation disappears.

Project switches, unmount, React StrictMode effect replay, late loads, late mutations, malformed/excess payloads, cross-project invitations, duplicate ids, cursor/revision overflow, stale epochs, and actor removal all fail closed. Stale callbacks cannot repopulate a prior project's membership or invitations. The adapter remains responsible for authenticated transport, server authorization, durable invitation filtering, diagnostics, and pagination beyond the bounded first page.
