# Cowork invitation redemption web panel

`CoworkInvitationRedemptionPanelModel` and `CoworkInvitationRedemptionPanel` are an adoption-ready, web-only redemption boundary layered after the audited one-time invitation creation panel. This slice has no production wiring. It renders nothing and performs no work unless a caller explicitly injects both a redemption client and a server-authenticated pre-membership identity. The component creates no timer, fetch, socket, RPC, subscription, storage entry, provider request, agent prompt, process, device key, project opener, or background task.

The operator must enter the shared-project identifier, 43-character base64url one-time token, and a display name of at most 128 characters directly into required form fields. The panel never obtains a token from a URL, query, hash, browser history, storage, logs, diagnostics, automated clipboard access, email, synchronization payload, provider output, or agent context. Changing the explicit project clears the form's token. Submission removes the token from React form state and the DOM immediately. The panel deliberately retains only the in-memory immutable command needed for an exact retry while the injected adapter is resolving; JavaScript engine, Promise, browser, and adapter internals may retain transient copies that this component cannot enumerate or erase.

The model strictly decodes the injected pre-membership identity and binds its exact session, user, and device to one deeply frozen `{ expectedIdentity, request }` command. The request also binds one command id, shared-project id, token, and normalized display name. A rejected or synchronously thrown transport call is an indeterminate acknowledgement because the authenticated server may already have committed it. Retry reuses that exact object and id; it never reads the cleared form, reconstructs a secret, generates a replacement command, or silently changes project, identity, device, or display name. The operator may instead discard the retry capability, which drops the retained command and returns to an empty form.

The existing `CollaborationMembershipMutationResult` deliberately contains no project or device fields. This panel does not invent them. Project and device binding comes from the exact expected session binding plus the server store's independently authenticated, identity-bound idempotency receipt. The decoded result must contain a non-owner member whose user id and display name exactly match the expected identity and immutable request, whose permissions fit the returned role, and whose membership epoch is positive. Both `applied` and `already-applied` are valid because a retry can either perform the previously uncommitted operation or recover its receipt.

The identity in this renderer model is expected-result and retry-scope evidence, not a credential and never proof of authentication by itself. A production RPC must derive the redeeming identity from its authenticated server session, must not trust or deserialize a renderer assertion as `CollaborationAuthenticatedIdentity`, and must call the audited membership store with that server-derived identity. If the adapter serializes the request, it must omit the renderer identity entirely. It must also reject a local expected identity that does not match the authenticated session before dispatch, without putting either identity or the token into an error. This prevents the web shape from accidentally becoming a client-forgeable version of the store's internal `{ identity, request }` boundary.

Adapter results must be bounded, intrinsic-prototype JSON-like graphs containing only enumerable own data properties. That response boundary rejects inherited, accessor-backed, symbol-bearing, sparse, decorated, oversized, subclassed, Proxy-wrapped, excess-field, malformed, cross-user, name-drifted, privilege-escalated, null-member, and impossible-epoch data. Exported-model command input is instead snapshotted from the exact expected own data descriptors before command-id creation: accessors are rejected, and a transparent Proxy cannot make its `get` trap run or change the captured command. This avoids using `structuredClone` on the one-time token merely to detect a harmless wrapper, which would manufacture another secret string copy. Accepted command and display data is copied and frozen. Definitive decode or semantic errors clear the command/token reference and require a new explicit token. Success, discard, client or identity replacement, unmount, stop, and stale/superseded callbacks likewise drop sensitive request state; late results cannot repopulate an old context. Form state is owner-tagged so React cannot paint an old scope's token or other fields during the render before replacement-effect cleanup. Reentrant command-id factories and synchronous state observers cannot dispatch after closing or replacing a scope.

JavaScript strings, promises, and browser heaps cannot be securely zeroed. The panel guarantees prompt reference removal from its own form/model state transitions, not physical memory erasure. Injected adapters must not log, persist, diagnose, cache, synchronize, or otherwise retain the command or response. This slice deliberately adds no production transport, membership RPC, persistence, email delivery, clipboard helper, timer, filesystem access, device enrollment or key generation, project opening, provider integration, or agent integration.
