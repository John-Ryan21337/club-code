# Club Code Operator Feature Canon

Status: authoritative operator-request ledger. This document preserves product
intent; it does not upgrade a proposed or partially validated capability to a
shipped feature. Implementation truth remains in the linked subsystem canons,
source, tests, and exact release evidence.

## Product direction

Club Code is an ambitious, operator-controlled collaboration and atmosphere
cockpit built on Cafe Code compatibility surfaces. Its purpose is not Cafe
Code's former "tiny-window" minimalism. It may grow richer visual, telemetry,
media, workflow, provider, and coworking surfaces when they remain bounded,
truthful, reversible, understandable, and safe with paid model usage.

User-facing branding, examples, package instructions, hero art, and commands
must say Club Code. A Cafe Code name may remain only where an upstream package,
stored-data directory, protocol, application ID, or compatibility command still
requires it. Public README art must use the approved Club Code hero while
retaining the separately approved character image.

## Status and evidence rules

- **Implemented** means the production path exists inside its documented
  boundaries.
- **Landed - validation pending** means source and focused evidence exist, but
  the required composite or live gate is incomplete.
- **Partial** means a safe subset exists and the remainder stays explicit.
- **Planned** means this ledger preserves the requirement but no production
  path may be claimed.
- A branch, setting, fixture, design, build, running process, shortcut, pushed
  commit, and GitHub PR are separate evidence. Never infer one from another.
- Stale lane work is input for review, not release evidence. Recover it from
  the preservation ledger, compare it with current source, and adopt only a
  bounded non-overlapping slice through normal gates.

## UI language and bilingual learning mode

The [UI Localization canon](./ui-localization-canon.md) is controlling. Club
Code provides a persisted renderer-local choice among **Follow system**,
**English**, **日本語**, and **English + 日本語**. The dual mode presents compact
labels as `English / 日本語` and longer descriptions or warnings in clearly
separated English-first and Japanese-second forms so a learner can associate
both meanings without changing modes.

The selected mode covers first-party buttons, navigation, settings, choices,
descriptions, help, dialogs, warnings, statuses, tooltips, accessibility text,
and packaged automation templates. It never translates chat transcripts,
provider output, code, terminal output, file or directory names, URLs,
identifiers, secrets, or operator-authored prompts. English and Japanese copy is
authored and reviewed rather than generated by a runtime model or network
translation request.

Steady Progress, Hardcore Fanout, and Idle Thread Guard have explicit English,
Japanese, and bilingual built-in variants. A language change may migrate only
an exact recognized Club Code built-in; custom prompt text is preserved
byte-for-byte. Bilingual automation templates are longer and may consume more
provider input tokens, credits, quota, or money, so the UI carries a direct
warning and makes no cost guarantee.

Language selection is presentation only. Selecting, resolving, or migrating a
language must never enable, arm, re-arm, reset, dispatch, retry, change a cap or
idle interval, create completion/idle authority, or bypass Stop and manual FIFO
priority for either automation.

## Paid automation safety

### Auto Nudge

The [Auto Nudge canon](./auto-nudge-canon.md) is controlling. These points are
non-negotiable:

- Auto Nudge is default off and exact-thread scoped.
- Only a newly observed, provider-confirmed completed response may authorize
  one immediate follow-up after accepted operator FIFO work drains.
- Time is never dispatch authority. There is no nudge delay, periodic tick,
  inactivity trigger, minute setting, 30-minute ceiling, elapsed run ceiling,
  or timer-based retry.
- Transcript movement, a running/starting/connecting turn, pending approval or
  input, an unsent local draft visible to the dispatcher, accepted manual work,
  stale authority, Stop, or an exhausted cap must prevent dispatch.
- Every send is a visible ordinary user message and may consume real paid
  tokens, credits, quota, or money. English and Japanese UI/docs must carry a
  direct alpha/no-warranty/own-risk warning; Club Code offers no reimbursement
  or guarantee against provider charges.
- The controls are centered over the prompt manuscript, not stretched across
  the entire application. When both are expanded or collapsed, Auto Nudge is
  the left half and Idle Thread Guard is the right half, with comparable
  red/green Off/On presentation.
- Built-in defaults are application-wide defaults for every thread. Exact
  recognized legacy defaults migrate; operator-authored text does not.

The exact **Steady Progress** built-in text is:

> Continue from the current thread context; do not restart discovery or reread settled material. Re-anchor to unresolved operator requests and the project's applicable handoff, plan, canon, and current PR/backlog state. Reuse a compact progress packet when present; refresh external state only after a relevant change or when stale. Select the highest-priority unblocked operator ask, keep at most two coherent lanes, implement the next verifiable slice, and update canon only when evidence or operator intent requires it. Linear owns actionable status and dependencies; Notion owns durable decisions and research; link rather than duplicate. Stop and report when the plan is complete, progress is blocked, or new authority is required.

The exact **Hardcore Fanout** built-in text is:

> Continue from the current thread context; do not restart discovery. Re-anchor to unresolved operator requests and the project's applicable handoff, plan, canon, and current PR/backlog state. Reconcile external state once per bounded run, then refresh only after a relevant change or when stale. Drive the highest-priority unblocked asks through bounded, non-overlapping parallel lanes with one owner per lane; never fan out duplicate investigation or implementation. Give each lane a compact context packet, converge through repository gates and required independent audits, and update canon only when evidence or operator intent requires it. Linear owns actionable status and dependencies; Notion owns durable decisions and research; link rather than duplicate. Stop fan-out when lanes contend, context cost exceeds its value, work is complete or blocked, or new authority is required.

### Idle Thread Guard

The [Idle Thread Guard canon](./idle-thread-guard-canon.md) is controlling.
Idle Thread Guard is separate from Auto Nudge and cannot mint or consume Auto
Nudge completion authority.

- It is default off, exact-thread scoped, and observes a running turn that has
  stopped producing transcript/tool/session activity.
- Any meaningful projected activity resets its clock, so continuous background
  work prevents a send.
- The hard minimum is one hour; the accepted range is 1–720 whole hours, the
  default is two hours, and multi-day values such as 48 hours are valid.
- One idle episode may send at most one visible status request. It persists its
  one-shot barrier before transport and cannot re-arm until newer activity.
- It never interrupts the provider. Indeterminate or rejected transport fails
  closed rather than retrying.
- UI/docs must warn that even a status request may consume paid tokens while
  legitimate long work is still happening and must warn against low values.

## Provider runtimes and models

Provider Settings exposes two runtime sources for Codex and Claude:

- **System CLI** uses `codex` or `claude` from `PATH`, or the operator's explicit
  binary path. It is the portable/default choice and leaves installation,
  updates, compatibility, authentication, and version pinning under operator
  control.
- **Bundled runtime** currently means Club Code's **Windows-only managed
  install**, not provider binaries compiled into the repository. The installer
  copies its packaged Node/npm into the user-local managed root and installs
  `@openai/codex` and `@anthropic-ai/claude-code` beneath that root. It does not
  change system `PATH` or global npm packages.

Managed mode offers predictable app-owned paths, easier first installation,
separation from global npm state, and a managed login launch path. Its limits
must remain visible: it is Windows-only today, installation may require npm
network access, current package resolution is not a reproducible pinned supply
chain, and failed/missing installs must show unavailable rather than silently
falling back to a system CLI. Cross-platform setup continues to use System CLI
until an independently tested managed package exists for that platform.

LM Studio remains available for full Codex local-provider work and as a
separate narrow Atmosphere Console fallback. The Atmosphere Console uses a
zero-token deterministic parser first, then may use a bounded LM Studio,
Codex, or Claude control-sentence fallback with lightweight/flash-class models
prioritized. It receives no transcript, source, credentials, or broad tool
authority.

## Prompt, workflow, and operator surfaces

- Preserve exact-thread drafts, visible manual FIFO follow-ups, provider-native
  steering only when active-turn evidence proves it safe, Stop authority, and
  recovery after provider-requested input.
- Composer attachments include images, bounded text files, and an explicit
  camera workflow with preview, front/rear choice, retake, video-only browser
  permission, and system-camera fallback. Camera content is never captured in
  the background.
- Workflow and workspace observatories show only provider-observed truth.
  Prompts, hidden reasoning, secrets, raw SQL, arbitrary command output, and
  invented traffic are never visualization input.
- Provider usage, quota, cache, compaction, pacing, and cost displays must label
  source and staleness. Automatic pacing remains advisory/planned unless hard
  spend, evidence, routing, and Stop gates are proven.
- Settings profiles include only exhaustively classified safe presentation
  fields. They never move credentials, provider/account routing, automation
  authority, consent, identity, or host-control state between profiles.

## Matrix, atmosphere, and GPU rendering

The [experience canon](./ambient-experience-canon.md) owns exact renderer
behavior. The operator-requested contract is:

- Modes are Flat, Forward, Reverse, Warp, Walk Forward, and Walk Reverse. Every
  mode retains truthful provider-activity connectors when evidence exists;
  visual absence must not be an accidental mode-specific regression.
- A provider-confirmed agent launch draws its bounded AGENT -> DISPATCH route
  immediately. Club Code does not wait for the delegated task to finish, and
  the later completion cannot duplicate the same route.
- Walk glyphs spawn randomly throughout the visible viewport, not only along
  its top or bottom edge. A lifecycle falls the selected percentage of page
  height, then fades fully and reconnects routes to newly spawned glyphs.
- Walk Forward grows from the selected small endpoint to the large endpoint.
  Walk Reverse shrinks from large to small. Lifecycle progress is independent
  of viewport wrapping.
- **Motion from center wind intensity** is an adjustable 0–10 outward force.
  Glyphs near center receive little lateral velocity; glyphs farther left or
  right move increasingly outward on their respective side.
- Density reaches the requested high range: a bounded 640-stream source pool
  and setting through 10 support roughly three-to-four times the former
  population. Forward and reverse admission must remain comparable.
- Two-dimensional projected occupancy uses each glyph's actual font bounds so
  large glyphs and long safe basename labels do not overlap. A filename may be
  clipped or elided safely when required, but it must never be width-scaled or
  horizontally compressed into unreadable text.
- Activity connector endpoints attach to scaled glyph edges. Stroke, packet,
  trail, and endpoint geometry interpolates between the actual font sizes at
  both ends: distant/small ends taper and near/large ends flare. Non-Walk modes
  keep their own correct geometry.
- White/black flashes are release-blocking. Canvas2D draws into a detached
  bitmap and atomically presents it without visible clears or dimension
  resets. The WebGL2 path uses bounded instanced glyph-atlas rendering and a
  synchronized Canvas2D overlay/fallback. Context loss, insufficient limits,
  or a failed GPU frame must fall back without a blank compositor frame.
- WebGL2 is true GPU glyph composition where capability diagnostics select it.
  Canvas2D remains required for snow/rain, connectors, and fallback;
  OffscreenCanvas worker use remains a future optimization rather than a false
  shipped claim.
- Reduced motion, device-pixel ratio, particles, glyph cache, draw counts,
  opacity, and background animation are bounded.

Matrix palette options include fixed, rainbow, per-stream rainbow, and
music-reactive modes; shimmer speed is independently adjustable. Optional
Roman/Japanese mix, coding vocabulary, 2ch-inspired glyphs, and intact cat AA
stay separately controllable. RGB synchronization is default off and remains a
safe provider-neutral boundary until a reviewed loopback-only OpenRGB adapter
can truthfully inventory supported controllers. It must not scan arbitrary
executables, invoke proprietary RGB tools, use raw HID/SMBus authority, or
claim AORUS, G.Skill, Redragon, keyboard, RAM, or case-light support without an
adapter-confirmed device and live test.

## Ambient media and presentation

- Ambient image/GIF, YouTube, world clock, and Atmosphere Console surfaces are
  movable, resizable, viewport-clamped, disableable, and do not reserve prompt
  transcript height. The console is transparent at the same design level as
  the world clock.
- Media includes persistent validated image/GIF assets, a bounded directory
  cycle, YouTube/Spotify embeds, direct local media, desktop VLC, Theater and
  Cinema layouts, adaptive edge glow, Spectrum, and the bounded bundled
  MilkDrop/Butterchurn catalog.
- The curated first-run presentation profile carries the approved window
  positions and EDM YouTube queue. Defaults apply only to missing fresh-install
  settings and never overwrite an operator's existing personal layout,
  playlist, assets, consent, or credentials.
- Native YouTube fullscreen cannot retain Club Code rails; Cinema is the
  supported in-app presentation. Cross-origin iframe pixels cannot be claimed
  as live Ambilight evidence.

## Project Resources, telemetry, and profiles

- Project Resources covers truthful CPU, memory, storage, GPU, and temperature
  signals only when the host adapter actually supplies them. CPU/RAM
  temperature is not universally exposed by Windows or motherboard firmware;
  absence is a capability result, not zero.
- **Hide unavailable graphs** removes the entire unavailable chart surface. It
  must not leave an empty plot, synthetic zero line, stale last value, or an
  "unavailable" chart card behind. When the option is off, unavailable state
  remains explicit and visually distinct from a measured zero.
- Sampling pauses or reduces while hidden, bounded histories cannot grow
  without limit, and failures remain isolated from provider work.
- Profiles and telemetry remain parallel product priorities, but profile
  portability never expands into machine-specific sensors, secrets, or
  automation authority.

## Secure coworking suite

The [secure coworking architecture](./secure-coworking-architecture.md) is the
controlling security and delivery contract. Preserve all of these goals:

- invited multi-user shared projects; protocol ceiling 128, initially supported
  limit 20 members/editors and eight concurrent agent runners until load tests
  justify more;
- merged and side-by-side authored prompt histories, shared project transcript,
  separate operator-to-operator chat, presence, tasks, claims, dependencies,
  bounded agent messages, asynchronous and realtime updates;
- compact versioned context packets and deltas instead of replaying the whole
  transcript to every agent;
- outbound authenticated encrypted collaboration transport, project-scoped
  authorization on every operation, device identities, membership epochs,
  revocation, audit attribution, idempotency, monotonic replay, and bounded
  snapshots;
- a locally chosen managed replica root, content-addressed blobs, staged hash
  verification, path-containment/no-follow materialization, explicit conflicts,
  recovery-only tombstones, and no peer authority to erase another operator's
  local source or recovered version;
- shared agents confined by an OS-level container/VM-equivalent sandbox with
  only the managed replica mounted, default-deny egress, no host credentials,
  home directory, arbitrary dialogs, hooks, installs, or executable launches;
- safe database coordination: never live-copy SQLite databases or WAL/SHM and
  never guess a row merge. Prefer an authenticated external database service;
  otherwise use private forks plus consistent engine backup/logical export, or
  a fenced server-authoritative serialized head with short writer leases,
  compare-and-swap hashes, and reviewable conflict artifacts.

Current collaboration foundations do not equal a shipped cross-network room.
Network transport, durable membership/invites, device enrollment, room UI,
materialization, sandboxed runners, and live synchronization retain their
explicit phase status until implemented and independently audited.

## Local agent execution safety

- A Codex spawned-agent ceiling belongs to the thread. It is not a one-prompt
  launch hint. The supported range is 1 through 128. Changing it restarts the
  provider session without changing queued prompt order or steer semantics.
- Club-launched Codex, LM Studio, Claude, and OpenCode provider runtimes start
  at the operating system's below-normal process priority. Shell-launched
  descendants are also lowered after they appear. New agent subprocesses then
  inherit the provider runtime's lower scheduling class.
- Lower process priority reduces CPU contention during large agent batches. It
  does not reduce the selected agent limit, model behavior, visual quality, or
  provider authority. It also does not claim to cap RAM, GPU, disk, or network
  use.
- A host that rejects the priority request may still start the provider. Club
  logs that condition instead of turning a workstation scheduling safeguard
  into a provider outage.

## Distribution, shortcuts, documentation, and upstream adoption

- Desktop and Start-menu shortcuts must target the exact latest validated local
  release checkout/build. Updating source or GitHub alone does not update a
  shortcut or running process, and a client must not be restarted without
  operator authorization.
- README/setup guides must be LLM-friendly for Windows 10/11, macOS,
  Arch Linux, and Raspberry Pi 5. They may recommend asking Codex or Claude Code
  to perform the documented setup, but commands must install/build Club Code,
  not accidentally clone, publish, install, or launch Cafe Code.
- English and Japanese current-build sections must carry equivalent technical
  detail and unmistakable legal/safety warnings. Japanese personality may be a
  deliberately drunken Kabukicho-hostess voice only outside the plain warning
  blocks; style must never weaken safety, privacy, alpha, or no-warranty text.
- Cafe Code adoption work should be granular and dependency-ordered. Each PR or
  hosted agent note states its exact slice, prerequisites, security boundary,
  tests, and cherry-pick/adaptation steps so upstream maintainers can adopt one
  feature without importing the whole Club Code suite.

## Permanent honesty boundaries

- Do not claim support for an unavailable provider, sensor, GPU path, RGB
  controller, platform package, weather entitlement, embedded-player feature,
  database merge, or coworking security property without direct evidence.
- Do not expose prompts, provider credentials, hidden reasoning, absolute local
  paths, unrelated files, or personal directories through telemetry,
  visualization, sharing, diagnostics, or public artifacts.
- Do not trade paid-token safety, operator Stop authority, sandbox containment,
  no-remote-delete recovery, or source-of-truth accuracy for visual polish or
  autonomous convenience.
